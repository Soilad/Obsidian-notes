# User manual
Document explaining how to **use, operate, install, maintain, or troubleshoot** a product, device, machine, application or system.

> Not meant to be read cover to cover — used as a **reference guide**.

# Types
| Type | For | Purpose |
| --- | --- | --- |
| **Instructional** | End users | Introduce product, setup, step-by-step tutorials, troubleshooting |
| **Training** | New employees | Complete a specific task, project or job; onboarding |
| **Service** | Technicians, engineers | Care and maintenance, troubleshooting, repairs |
| **Operation** | Company/organisation | Roles, responsibilities, processes |
| **Organisational policy** | Employees | Policies, procedures, best practices |
| **SOP** | Users of established procedures | Specific instructions for standard procedures |

# ⭐ Structure
1. **Title** — what the manual is about
2. **Purpose / Introduction** — the product and its purpose
3. **Requirements / Materials** — anything needed beforehand
4. **Instructions / Procedure** — steps in correct order
5. **Warnings / Precautions** — what may cause damage or injury
6. **Troubleshooting** — what to do if a common problem occurs
7. **Maintenance** — how to clean, store, maintain

# Five essential qualities
1. **Plain language** — write for the user, not the developer. No unnecessary acronyms, buzzwords, slang. Clear and professional, but not oversimplified.
2. **Simplicity** — short sentences, headings, bullets, numbered steps. Avoid large blocks of text.
3. **Visuals** — images, diagrams, screenshots, **annotated** visuals highlighting buttons and parts. Show rather than only explain.
4. **Focus on the problem to be solved** — explain each feature in terms of the problem it solves, not as a feature list.
5. **Logical hierarchy and flow** — basic first, then advanced; consistent structure throughout.

# How to create one
1. **Identify the users** — their knowledge, skills, needs determine tone and detail
2. **Focus on the problem** the manual should solve
3. **Use sequential steps in order** — follow them yourself to check nothing's missing
4. **Map the user journey** — from the user's problem to the solution
5. **Choose a template** — consistent fonts, sections, numbered steps, highlighted warnings
