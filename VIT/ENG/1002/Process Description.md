# Process description
Clear, systematic explanation of **how something is done, how something works, or how something happens** — the steps, stages or sequence involved.

# Four types
| Type | Explains | Examples |
| --- | --- | --- |
| **Business** | Steps of a business activity | Processing an order, handling a complaint |
| **Manufacturing** | How a product is made/assembled | Assembling a mobile phone |
| **Scientific / Research** | Steps of an experiment or study | Conducting an experiment, analysing results |
| **Technical** | How to use, install, operate, repair | Installing software, setting up a network |

# Five elements
1. **Clarity** — plain language; jargon only if the audience knows it
2. **Sequential steps** — logical order, each flowing from the previous
3. **Specificity** — enough detail for the reader to actually do it
4. **Consistency** — same format, terminology and tone throughout
5. **Visual aids** — diagrams, charts, pictures for complex processes

# Structure
**Introduction** → what process is described · what it achieves · how many major stages
**Body** → the stages in correct chronological/logical order
**Conclusion** (useful when long) → final outcome · completion · summary of final stage

# How to write one
1. **Know the purpose** — work process? experiment? technical procedure?
2. **Know your audience** — simple language for beginners, technical terms for experts
3. **Divide into steps** — don't skip, don't add unrelated information
4. **Use action verbs** — *insert, click, mix, boil, press, connect, remove*
5. **Give specific details** — measurements, time, temperature, conditions
   - ❌ Boil the water. → ✅ Boil the water **for 5 minutes**.
6. **Review and edit** — ideally have someone else try to follow it

# Core principles
- **Chronological order** — if a step must happen before another, the writing must reflect that dependency
- **Clear, precise language** — ❌ "do the thing" → ✅ "tighten the valve clockwise until resistance is felt"
- **Transition signals** — signposts so the reader doesn't lose their place
- **Completeness without overload** — every essential step, no burying in detail

# Transition signals
| Kind | Shows | Examples |
| --- | --- | --- |
| **Sequential** | Order of steps | first, second, next, then |
| **Temporal** | When an action occurs relative to another | meanwhile, during, while, after, before |
| **Conditional** | Step happens only if a condition is met | once, if, when, as soon as, provided that |

# Common errors
| Error | ❌ | ✅ |
| --- | --- | --- |
| Wrong sequence | "Finally, the raw material is collected." | "**First**, the raw material is collected." |
| Inconsistent tense | "The material **is cleaned**. Then the worker **heated**…" | Keep one tense throughout |

> Process description = **describing** a process (often passive, third person). [[User Manual]] = **instructing** a user (imperative, second person). Don't mix them up.
